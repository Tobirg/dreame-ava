# Dreame X50 / R2505

## Test context

- Model reported in the research: `dreame.vacuum.r2505` (Chinese variant).
- Root ADB survives reboot in the owner's setup.
- The robot was reset and waiting for app-based Wi-Fi provisioning.
- AVA ran with `/ava/conf/r2440.conf`; this configuration name does not prove
  compatibility with another commercial model.
- Exact firmware version: not yet recorded here. Analyzed binary fingerprints
  are recorded in the [static analysis notes](../research/ava-dispatch.md).
- Hardware observations below were supplied by the owner on 2026-10-24.

## Verified reads

All four MIOT-style properties returned `code: 0` through both vendor `avacmd`
and a Python client using ADB forwarding to the Unix socket.

| siid | piid | Property | Observed value | Interpretation status |
| --- | --- | --- | --- | --- |
| 3 | 1 | Battery percentage | 70 | Numeric percentage |
| 3 | 2 | Charge state | 2 | Enum meaning not yet established |
| 2 | 1 | Work mode | 2 | Enum meaning not yet established |
| 2 | 2 | Error code | 0 | Full error enum not yet documented |

The named getter returned battery `71`, charge state `not charge`, work mode
`14`, clean time `0` and clean size `0` in a separate request. These are strings.
The named and MIOT-style work modes must not be interpreted as the same enum.
Static analysis found a `CalculateWorkMode()` conversion; an exhaustive mapping
has not been validated. The requests were separate observations, not an atomic
snapshot proving an exact enum correspondence.
